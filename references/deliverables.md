2. 沪主板：注册、委员会、在审、首次、现金重大购买/出售，各自顾问排名及我司项目。
3. 深主板：同类结构。
4. 科创板：同类结构。
5. 创业板：同类结构。
6. 北交所：同类结构，不能因Excel缺北交所分榜页就省略；直接从北交所明细生成。
7. 在审项目详情：按五板，项目、代码、最新有效状态、金额、独立财顾。
8. 本期新披露案例简介：首次预案/首次草案分开；收购和现金重大出售/置换按实际交易表达。

## A股市场并购重组动态

- 整体：本周/全年首次披露、本周/全年受理和当前在审及当年受理子集、我司清单、通过、简易、注册、受理后终止。

## 市场周报PPT

参考第43期20页内容，章节为：市场数据、市场重要事件、案例解析、IPO终止简报、子公司引战/专业机构合作、法规/热点。页数随本期内容变化，不保留空的旧案页面。

- 数据页：首次披露、当前在审、委员会及简易通过、注册榜/趋势；区分累计项目数及顾问家次。
- 重要事件：新预案、首次草案、受理、过会、注册、终止、控制权首次/完成、协议转让两表。一个事件多页叙述时数字与定义一致。
- 案例解析：从本期可验证材料选有代表性的交易，叙述交易结构、财务估值、业绩承诺、对赌/退出及值得关注的特点；结构图节点/比例/控制关系与正文逐项比对。无足够材料不填想象的商业协同或预测。
- IPO：本期清单、企业概况、终止阶段和原因，仅取可回源信息，不以主动撤回推断审核失败。
- 引战/合作：新增与进展分清；原币、估值基准、认缴/实缴、交割与回购分别表达。
- 更新原生图表中的series、分类轴、内嵌Excel、图上数值、标题和来源注，检查图例。若图表外链上期文件，修复为本期内嵌或明确连接。
- 页码/目录/章节编号跟随增删。检查比例、金额、交易路径在图/表/文字中一致，而非只改文字日期。

## v4.1 Word/PPT 已知差异与硬要求

第43期真实回放中，`build_reports.py` 生成的是 `clean-native` 精简稿：事实表可用，但与现场稿版式不等价。周报 6 页、现场 32 页；动态 4 页、现场 5 页；PPT 8 页、现场 20 页。`test_known_answer_43.py` 将其列为 WARN，而不是因为版式差异否定正确事件数。

下一轮必须按以下顺序处理：

1. 以最新完整上期 Word/PPT 为模板，保留目录、章节、表格、合并单元格、页眉页脚、原生图表和内嵌工作簿。
2. 将结构化事件卡填入模板指定表位；新增/删除行后同步目录、页码、章节编号、图例和图表数据，不直接覆盖整份文档。
3. 只有上期缺少相应角色时才使用 clean-native 降级稿，并在《待核说明》中明确“模板缺失/版式非等价”。
4. 正式 PDF 仅使用 Microsoft Word/PowerPoint“最适合打印”导出；LibreOffice 只用于自动化预览。验收同时要求事实表一致和渲染页视觉一致。

## 交付包装配

完成全部Excel和Office内容后，运行：

```bash
python scripts/materialize_package.py 工作目录/已核实内容 --out 工作目录/本期成果包 --pdf-source-dir 工作目录/office-pdf
```

输入目录必须恰含13个Excel、周报DOCX、动态DOCX和PPTX；PDF目录必须恰含三份与Office源文件同名的PDF及 `office-export-manifest.json`。脚本核对应用、导出方式、源/PDF哈希和原生页数/PDF页数，只装配已核实内容，不补写事实。输出目录必须尚不存在。`--preview-soffice` 只能生成 `preview/`，状态为 `PREVIEW_ONLY`，不得作为发布版。

## 修订、发布与视觉核验

- 保留Word原有修订/批注；本次新内容及修改均以HTLH归属。缺失的图片关系“NULL”等先登记，不能任意删页眉内容来使解析器成功。
- 语义提取排除w:del、w:moveFrom及删除行，保留w:ins、w:moveTo；Word API的paragraphs不足以包含表格/文本框，按实际载体遍历。移出旧行不可与移入新行一同算合计。
- 在临时副本对照接受修订后的净稿进行数据与版式核验，原有修订是否接受并生成发布PDF，以本期用户授权及已批准版本为准。未经确认的待复核稿应标状态，不冒称最终发布版。
- 导出PDF后逐页检查文字缺字、表格断行/表头、横竖版、单位、页眉/页脚、空白页、目录页码和图表清晰度。发现由字体替代造成的分页变化要复查，不能把渲染器缺字误报为源文件正文空白。
- 发布PDF使用Microsoft Word/PowerPoint电脑操控按“最适合打印”导出；LibreOffice只用于预览，分页或字体差异不得进入正式包。程序再以 `pdftoppm` 逐页渲染PNG检查。
- 交付文件均使用可点击绝对路径；不只提供目录，不能用相对路径导致桌面客户端无法打开。

## Word 审核与注册指标验收（2026-11-14 第45期录制后补充）

### 审核通过、审核总数和暂缓

Word 必须按当期明细重算以下两层，不得直接把聚合数当成单一子类：

- `审核通过 = 暂缓二次上会 + 简易审核 + 普通程序一次性过会`
- `审核总数 = 审核通过 + 否决 + 暂缓尚未二次上会`

第45期回归样例：`42 = 2 + 3 + 37`；`44 = 42 + 1 + 1`。这些数字只用于回归本期的拆分关系，不得写死为以后各期常数。

验收动作：

1. 从 0号 `重组委通过`、`重组委否决`、暂缓/二次上会明细生成“项目代码集合”，再按项目数而不是行数汇总；同一项目二次上会不得重复计为新增通过。
2. 说明“上会通过”时用窄口径并另列简易程序；说明“审核通过”时用宽口径。两句话不能引用同一分母而不说明口径。
3. “暂缓 N 单”必须说明是“仍暂缓”还是“含已二次上会通过的历史总数”；两种口径不得相加。
4. Word 总述、分板块表、PPT 与 Excel 汇总须逐项对账；任何一处出现总数、通过、否决、暂缓的组合无法还原，均不得发布。

### 券商 49 家次与 20 家机构的独立验收

- 42 单审核通过须另按财务顾问列统计家次，不可把“42 单”直接当“42 家次”。
- 第45期回归样例为 **49 家次、20 家机构**，并须与 0号「本年度各券商情况汇总」的 49 次逐项一致。
- 联合财顾每家各计 1 次；吸收合并双方顾问分别计次；换行、顿号、逗号、分号均为分隔符；先剔除角色标签，再按归一表统计。
- 券商名称集合、每家家次、合计家次三项必须同时核对；机构名归一不得把中信证券与中信建投合并，也不得机械删除所有“证券”后缀。

### 注册批复与金额联动

- 注册总数须与各板块分项之和一致，并与证监会三表“已注册/注册生效”及三所项目动态逐项交叉。
- “提交注册”单列，不计入“已注册”。
- 新增注册项目时同步更新注册金额；总述、板块表、明细、Word/PPT 的数量和金额必须同轮联动。
- 第45期录制时观察到 Word 总述写“37单注册”，但分板块 `沪12＋深10＋科创8＋创业4＋北1` 合计仅 35；另有创业板“本期无新增”的待核表述。本节只登记待核，未修改原 Word，见 [word-metrics-demo-45.md](word-metrics-demo-45.md)。

### 在审项目与新增受理

- Word/动态的“当前在审”必须来自按最新有效状态重建的在审清单，并已纳入本周新增受理。
- 检查本周是否出现“重组报告书（草案）（申报稿）”；关键词必须是“申报稿”，且只作辅助信号。
- 受理日以交易所项目动态或受理公告为准，不以列表更新日、报告书日或新闻日替代。第45期民爆光电为本周受理检查样例。
