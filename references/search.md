## 并购检索组：两个用途分别保留

首次发现：预案、草案、报告书、发行股份购买资产、发行可转换公司债券购买资产、重大资产购买/出售/置换、换股吸收合并、简易审核。`预案`与`报告书（草案）`分别入 `first_disclosed`/`first_draft`；仅“筹划/停牌/预挂牌”入 `lead_signal`。

存量进展：受理、问询/回复、修订稿/上会稿/注册稿、恢复/中止、重组委会议安排及结果、注册/批复、终止/撤回、实施/过户/新增股份上市、配套募资发行结果。

“修订说明、差异对照表、摘要”可按文件角色去重，**不把其含有的进展信息整体丢弃**。终止要区分筹划、方案后、受理后、过会后和配募终止；同一案多份后续自查/说明会公告不新建交易。把“协议”等词一概设为终止搜索排除词可能漏掉核心终止公告，先宽搜后正文分类。

## 巨潮检索：北交所（920/8/4 代码）必须用公司名称检索（2026-11-13 用户指出错误后实测确立）

**用户原话**：「巨能股份转让对价与受让方未能取得——巨潮资讯能查到吗？另外，和微信公众号核对过吗」

**我的错误**：2026-11-13 处理巨能股份（920578.BJ）时，用 `searchkey=920578` 检索巨潮返回 0 条，又试 `bse.cn` 直链遇 302 重定向循环，遂判定「无法取得全文」，把转让对价与受让方标为「待核」。用户质疑后重测：**用公司名称 `searchkey=巨能股份` 检索，巨潮返回 4 条完整公告，PDF 可直接下载**，转让价款 7,927.5 万元、每股 17.50 元、受让方宁夏共享集团全部取得。艾能聚（920770）同理，`searchkey=艾能聚` 返回 4 条。

**根因**：巨潮 `hisAnnouncement/query` 对北交所代码的索引方式与沪深不同——**`searchkey` 传 920/8/4 开头的代码匹配不到，必须传公司简称或全称**。`column=szse` 与 `column=bj` 实测返回相同结果，不需要改 column。此前把「代码 0 命中」误判为「巨潮不收录北交所公告」，是错误结论。

**强制执行规则**：

1. **北交所标的检索一律用公司名称**：`searchkey=<公司简称>`（如 `巨能股份`、`艾能聚`、`科创新材`），不得只用证券代码。代码检索仅作辅助，0 命中不能作为「无公告」的证据。
2. **不得因单一通道失败就判定「无法取得」**：按以下顺序逐级尝试，全部失败才可记 `LIMITED` 并说明已试路径：
   - 巨潮 `searchkey=<公司名称>`（首选，PDF 可直下）
   - 见微 `search_announcements`（`market:"main"`，label 用代码或简称，可取摘要与详情页）
   - `bse.cn` 官方原文（有 302 重定向循环与 Cookie/JS 挑战，需浏览器）
   - 交易所项目动态页（结构化状态，无正文）
3. **`bse.cn` 的 302 循环不等于公告不可得**：巨潮已同步北交所公告，优先走巨潮。记录「bse.cn 302」时须同时写明「巨潮已取得」，避免误导为覆盖缺口。
4. **「待核」只能用于真正穷尽通道后的缺口**：任何标「待核」的字段，必须在备注中列出**已尝试的通道与各自结果**（如「巨潮按代码0条、按名称4条已取得；bse.cn 302」），不得只写「未取得」。

**实测对照（2026-11-13，公告日 2026-11-13）**：

|---|---:|---:|
| `searchkey=920578`（代码） | 0 | 0 |
| `searchkey=巨能股份`（名称） | **4** | — |

## 控制权检索组

“控制/控股＋变更”、“实际控制人”、“详式权益变动报告书”、“收购报告书”四组交叉，并以“过户、无偿划转、表决权、一致行动、重整、司法拍卖、要约”补充。

识别实控人A→B、共同控制人组合变化、由有实控人变无或相反。仅控股股东改变且最终实控人未变，不能自动纳入实控人变更库；列候选并按当期确认口径归类。正文说“本次过户尚未导致变化”可能只指某一步，应结合该公告上下文、后续已披露董事会改组等安排判断，不能一句否定就删掉整笔正在推进的控变交易。没有固定“必须持股30%”标准。

**2026-11-12 第 2 段演示补充（防漏检，证据见 [review-demo-part2.md](review-demo-part2.md)）**：录制中标题「包含以下全部关键词」用 `控 变 提示 公告`，「不包含以下全部关键词」用 `刻度 整数倍`（另见 `持续督导`、`意见`），并打开风范股份收购报告书、建研院／路畅科技要约收购报告书、青岛食品与亚玛顿控制权拟变更提示性公告、中远通一致行动人协议到期不续签提示性公告。**这些是当次降噪用的演示词，不替代本节四组交叉与其他控制权覆盖组，不写成全局检索配置**；页面占位文案不能独自证明多排除词的布尔语义，换工具时须核对。

## 协议转让两表

主候选并集：权益变动报告书、简式/详式权益变动、协议转让、股份转让、控股股东、实际控制人、一致行动人；正文核对变动性质、转让双方、持股排序、转后控制安排。

旧skill建议 `announcementType=01011101` 等分类码，可作为**经实时验证后的补充筛选**；不能当唯一可靠手段，不硬写历史抽样“漏报80%”为全市场事实。接口不返回分类码时继续关键词/官方栏目并集，列明覆盖情况。

12表：权益变动方式为协议转让，转让方为上市公司控股股东、实际控制人或其关联方，且受让方不是上市公司控股股东、实际控制人或其关联方。13表：权益变动方式为协议转让，受让方不是上市公司控股股东、实际控制人或其关联方，且本次变动后成为上市公司第二大股东。两表可重叠，不按公司去重跨表删行。

简式权益变动报告书是 12/13 号的核心正文入口，但最终覆盖仍须完成主候选并集和逐份核验。归表按以下两步判定：

1. **12号**：权益变动方式为协议转让；转让方为上市公司控股股东、实际控制人或其关联方；受让方不是上市公司控股股东、实际控制人或其关联方。三项同时满足，纳入 12号。
2. **13号**：权益变动方式为协议转让；受让方不是上市公司控股股东、实际控制人或其关联方；本次变动后受让方将成为上市公司第二大股东。三项同时满足，纳入 13号。是否成为二股东，必须比较变动后受让方持股比例与其他股东持股比例；简式权益变动报告书未披露变动前后股权结构时，通过年报、Wind 或同花顺 MCP 等渠道补查并分析。不能仅凭“减持/受让”标题或孤立持股比例下结论。

12/13 号可重叠，不跨表去重删行。“持股差异不大”无量化定义时列边界案例待确认，不自创比例门槛。

零新增必须满足以下证据链：主候选并集已完成、分页翻到底且总量可证、候选逐份正文核验完成、排除理由可追溯，覆盖状态才可记 `COMPLETE`。用户明确确认无模板口径内交易时，数量记 `0`；在检索台账和《编制与待核说明》留存检索日、易董入口、关键词、排除词、候选数量、翻页覆盖、零新增结论、排除案例及理由。Excel 不新增空行、不改既有行、不标绿、不凑案例。

集中竞价、大宗交易、司法拍卖及司法裁定“以物抵债”、继承、主动减持、可转债转股及股权激励归属导致被动稀释、ETF 份额变动等，不等同于协议转让或协议受让；但仍须结合公司身份、变动后持股排序和控制权结果判断，不能只凭交易方式机械排除。录制未展示某一步、关键帧缺失或检索日志不完整时，不得据此推断零新增。
