# 核验清单与交付状态

本技能自身负责周报勾稽，不以调用“申报文件全面复核”替代；该技能的申报披露要求不适用于周报。若用户另要求独立全面复核，再按其指定范围使用。

## 必做勾稽

1. 按五板分别计算首次披露/受理/当前在审/过会/注册，板块分项合计＝市场唯一交易数。首次披露表内多标的空代码续行不可多算。`预案`、`报告书（草案）`和`筹划/停牌线索`分栏计数。
2. 已披露财顾的交易数≤相同口径总数；顾问家次＝各顾问贡献之和，联合财顾使家次可大于项目数。每笔已纳入顾问须可核公告；非独立财顾不混。
3. 券商左展示榜和右全表按名称集合一致、数值一致；无重复机构、无遗漏新增机构。占比分母与表注一致，舍入差异有说明，金额总计从唯一交易重建。
4. 我司项目清单项目数＝我司相同阶段统计；加总各板“我司”清单与汇总一致。已确定但未公开财顾的内部线索不混入公开排名。
5. 委员会场次与审议交易/次数分开；简易程序单列再按注释并入通过汇总；暂缓后二次上会不双算通过。
6. 本周新增只按对应事件日期落在区间判断；最新更新日不能伪装受理日。注册同理，公告日冲突时回原文核定再锁单数。
7. 在审桥接：上期存量＋新受理/恢复纳入/口径调整−过会/简易通过/在审终止等退出＝本期存量；恢复中止通常不增加原已计在审数。日期与事件重叠去重。最终以更新后三张“在审”表的`是否在审=是`去重代码数复核；第43期正文“49单”与表内48单不一致，必须显式列出，不能由脚本文本替换掩盖。
8. 控变：初始方案、最新方案和完成实际；交易方式、比例、金额、完成日期与旧备注互相支持。同一周首次且完成须在两类表中各出现一次，不误去重。
9. 12与13表分别判断资格，重叠交易清单明确；同名控制股比按表头一致映射，不强制改成不同口径。转让后第二大股东身份依据持股排序。
10. 各原币及单位分开，估值/作价/配募/最高收购金额分开；溢价率、PE、PB独立复算并核分母期间及对象。
11. 文本总述中的数量＝其后明细数量＝Excel汇总＝PPT数据；“本周无新增”不得与本周明细相冲突。“深、沪无新增”等复制错误须按交易所实际归属核。
12. 年度累计不是把各年度首次库总数相加；往年首披项目当年注册必须纳入注册数。跨年改名/换代码统一主体但保留方案身份。

## 程序与源文件保护

- 里程碑、状态、财务顾问和金额分别校验：标题命中里程碑不等于字段已回填；基础表中只写公告标题而交易标的/支付方式/金额/顾问空白的行应作为字段完整性警告。
- 投资/合作类表按公告事件计数，不能仅按证券代码判断重复；审核状态类表按证券代码和交易状态更新。新增与更新以`build-report.json`逐文件、逐sheet审计。
- PDF角色数量优先继承上期/用户要求。第43期现场只有周报与动态PDF；若用户明确要求PPT/PDF完整包，可额外生成但须标为增强产物。

- 运行inspect_templates对新旧文件盘点，检查表名、隐藏状态、合并、批注、图表、公式、外链及主要部件变动。公式错误=#REF!/#VALUE!/#DIV/0!/#NAME?/#N/A默认硬阻断。只有精确到文件、sheet、单元格且给出业务理由的allowlist可豁免；不得用“辅助区”整体豁免，也不得用最终交付稿作为自己错误的基准。
- 公式还必须有可读取缓存值。Excel重算后以OpenPyXL的 `data_only=True` 复核所有公式；无缓存、错误值、缓存与公式范围错位均硬阻断。版本历史或原文件曾含相同错误，不构成豁免。
- 不要求全表一律非空；检查本周记录的关键字段证据状态和待核清单。未披露不等于未检索，缺缓存不等于数值0。
- 按全部本周变动字段及受影响公式链重算；存量未变结果也需以独立汇总对账，基准版本相同不能证明原值无错。
- 三份发布PDF必须由 `office-export-manifest.json` 证明来自 Microsoft Word/PowerPoint“最适合打印”导出，源/PDF哈希与页数均匹配。LibreOffice PDF只能进入 `preview/`，不能计入发布文件。
- source台账与指标台账分开，脚本只能验证结构及所声明事件，不能识别伪造来源或判断事实真假。网页检索未全覆盖时即使脚本validation通过也只是部分完成。
- 原件哈希前后相同；用户期间修改源文件时停止向旧副本回写，保留旧快照并按新版本续作对比。不存在原件保护或已有人工内容覆盖风险时不要盲目retry。

## 复核收口与保存（2026-11-12 用户明确）

人工逐格复核的改动完成后必须按 `⌘S`（或点保存）并确认落盘；未保存不得称该表已复核完成，不得进入交付校验。用户 2026-11-12 明确「需要 `⌘S`／保存点击」；第 1 段复核录制未见保存动作，故此处列为显式收口步骤，证据见 [review-demo.md](review-demo.md)。

交付前另按 [workbooks.md](workbooks.md)「行业分类不得留空」跑合并单元格感知的全表空值扫描；空值未清零不得称行业字段已补齐。行业分类同样不得用 `待核` 占位（2026-11-12 第 2 段用户明确）。

- **先问制作人姓名**：人工逐步复核／诊断性编制开始前，先询问本期周报制作人姓名，不代填、不沿用上期；`auto_run.py` 无人值守主链路零提问不变。见 [review-demo-part2.md](review-demo-part2.md)。
- **单元格事实化复核**：抽查进展／备注单元格，确认不含统计口径括注、用户指令来源标注、公告编号页码锚点、取数渠道过程说明、期次归属判断；这些依据应在检索台账／全文核实台账／《编制与待核说明》中可追。见 [workbooks.md](workbooks.md)「进展叙述单元格写法」。
- **行情类字段**：「<首次披露年>年首次披露」sheet 的签署前一日收盘价、上市公司市值、股份转让协议溢价率须按 [accounting.md](accounting.md) 复算，不留空、不写待核。

## 说明及状态

《本期编制与待核说明》至少包含：范围/日期/期号、模板及版本、检索覆盖及受限来源、变动清单（字段及旧新值、来源）、关键勾稽、问题与未决口径、公式重算状态、Word修订和PDF发布版本、逐页视觉核验状态、原件保护、交付清单。

状态选择COMPLETE/PARTIAL/LIMITED/NOT_RUN/NOT_APPLICABLE，逐项说明影响；可解决的本轮技术问题先解决。脚本结构通过、Office结构通过、外部事实核验、全量覆盖与视觉核验是五种不同结论，分别写明。

对用户给已确认问题用直接措辞；疑似日期、币种、权利归属等保留双方和待决条件，不能静默选一个“合理值”。同一问题不要把计划与实际、完成归类、金额待核全塞进一句批注，拆成读者可操作的具体改项。

## 第45期录制后的硬门禁补充（2026-11-14）

以下门禁按当期明细重算；第45期具体数字只作回归样例，不作为后续固定目标。

### A. 审核指标三层勾稽

1. `Word审核通过 = 暂缓二次上会 + 简易审核 + 普通一次性过会`。第45期须通过 `42 = 2 + 3 + 37`。
2. `Word审核总数 = 审核通过 + 否决 + 暂缓尚未二次上会`。第45期须通过 `44 = 42 + 1 + 1`。
3. `0号重组委通过行数 = 上会通过行数 + 简易程序行数`。第45期须通过 `42 = 39 + 3`；且 `39 = 37 + 2`。
4. 独立重算“当前仍暂缓”和“暂缓后二次上会通过”，确认二者不重复；不得把 43 次重组委会议、其他口径 50 家次与 42 单、49 家次混算。
5. 任一公式不能由当期明细还原，或 Word/动态/PPT/Excel 任一处口径未注明，硬阻断。

### B. 券商家次门禁

1. 42 单审核通过对应的财务顾问须独立统计家次和机构数；第45期为 **49 家次、20 家机构**。
2. 与 0号「本年度各券商情况汇总」逐项对账：每家家次、机构集合、合计 49 三项全部一致。
3. 分隔符必须包含换行、顿号、逗号、分号；先去掉合并方/被合并方/吸并方等角色前缀；联合财顾每家各计 1 次；吸收合并双方顾问分别计次。
4. `（未披露）` 不算已披露；是否计入家次按明确口径处理，不得默认。
5. 名称按第45期归一表执行：华泰联合证券→华泰联合、申万宏源证券→申万宏源；中信证券与中信建投不得合并，其他名称不得机械去后缀。
6. 机构集合或家次合计任一不符，先查分隔符、换行和角色标签；脚本须用 3—5 行手工样本验算后才能报错。

### C. 注册批复门禁

1. 证监会主板、科创板、创业板三表须记录准确表名、截止日、已注册数和提交注册数；只统计“已注册/注册生效”。
2. 第45期回归：三表已注册 `22 + 8 + 6 = 36`，加北交所 1 单为 **37**；不得把 3 单“提交注册”混入。
3. 三所项目动态须逐项交叉注册项目、板块、注册日期和注册金额；未逐项完成时状态只能记 `PARTIAL/LIMITED`，不得写“全渠道核验完成”。
4. 新增注册项目须同步注册金额、总数和各板块分项；数量与金额不得一处更新、一处沿用上期。
5. Word 总数必须等于各板块注册数之和，并与明细及注册金额口径联动。第45期当前稿“37 总数 vs 分板块合计 35”为待核差异，未修复前不得发布。

### D. 在审新增受理门禁

1. 每期必须单独检查本周新增受理，并确认已纳入“当前在审”项目集。
2. 检查“重组报告书（草案）（申报稿）”标题，关键词必须含“申报稿”；该信号不能替代交易所项目动态或受理公告。
3. 受理日必须落在本期区间并有项目页/受理公告支撑；不得用最新更新时间或报告书日期替代。
4. 第45期民爆光电为本周受理检查样例；不得因未在旧在审表而漏计。
5. 三所状态、受理日或项目集冲突未解决时，在审数标待核，不得发布为确定值。
